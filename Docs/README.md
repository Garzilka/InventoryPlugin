# 📚 Документация проекта: процедурный мир и инвентарь

Мир строится **в рантайме из сида** и должен получаться **одинаковым у клиента и сервера**.
Монобиом: степь / лиственный лес. Платформа: Unreal Engine 5.8, C++ (`Source/UnrealWorld`).

Исходный черновик идеи — [`../Prototype.md`](../Prototype.md). Он сохранён как история: часть
решений в нём уточнена и изменена (см. раздел «Что изменилось относительно черновика»).

Второй большой блок проекта — **инвентарная экосистема**. Она уже существует в виде плагина
`Plugins/InventoryEcosystem` (13 модулей, ≈ 40 тыс. строк), поэтому по ней составлен не «план»,
а **контекст кода**: что есть, как устроено, что патчим и как оно стыкуется с миром.

## Глоссарий (простыми словами)

| Термин | Что это |
|---|---|
| **Сид** | Одно число, из которого рождается весь мир. Один и тот же сид → один и тот же мир |
| **Генплан (WorldDNA)** | Маленький набор данных на весь мир: размер, где горы, реки, дороги, города. Десятки–сотни килобайт |
| **Участок (chunk)** | Квадрат 256 × 256 м. Основная единица генерации, загрузки и синхронизации |
| **Супер-участок** | 4 × 4 участка (1024 × 1024 м). Используется для дальнего вида, чтобы не рисовать сотни мелких мешей |
| **Слой / маска** | Массив чисел на участок: «сколько тут леса», «сколько грязи», «можно ли копать русло» |
| **Правки игроков (Tier C)** | Список изменений мира игроками: выкопанная яма, срубленное дерево, колея. Единственное, что нельзя пересчитать из сида |
| **Хеш** | Короткий «отпечаток» данных (8 байт). Позволяет сравнить два мира, не передавая их целиком |
| **PCG** | Инструмент UE5 для процедурной расстановки объектов по графу правил |
| **HISM** | Компонент UE, который рисует много копий одного меша эффективно (лес, камни) |
| **RVT** | Текстура, в которую можно рисовать в рантайме. Через неё красится земля (трава/грязь/гравий) |
| **Юбка (skirt)** | Вертикальная «шторка» по краю меша участка, скрывает щели на стыках |
| **LOD** | Уровень детализации: вблизи сетка 1 м, вдали — 8, 16, 32 м |
| **Билинейный расчёт** | Вычисление высоты в любой точке по четырём соседним узлам сетки (смешивание по расстоянию) |
| **NavMesh** | Упрощённая карта проходимости для ИИ. В этом проекте — отложено, вместо него будет «сетка проходимости» |
| **ADR** | Architecture Decision Record — короткая записка «почему решили именно так» |
| **Предмет** | `UObject` (`UBaseItem`), а не актёр: живёт внутри владельца, переезжает вместе с ним. В мире показывается через `ABaseItemActor` |
| **Сервис предмета** | Подключаемый «модуль поведения» предмета (`UBaseItemService`): подбор, прочность, вид в мире, оружие, инвентарь внутри предмета |
| **Инвентарь** | Компонент-актёра: лента (слоты), сетка N×M или сетка с габаритами предметов (`Line` / `Grid` / `Spatial`) |
| **Стек** | Одна запись предмета с количеством (`Amount`), ограниченная `StackSize` |
| **Контейнер** | `ABaseContainer`: ящик/шкаф/труп. Держит инвентарь, умеет выдавать лут и респавнить его |
| **Лут-таблица (row)** | Именованный набор предметов с весами; из строк собирается выдача |
| **Пресет лута** | Переиспользуемый набор правил генерации, на который ссылается объект |
| **GUID лута** | `FName`-идентификатор лут-настройки объекта (`ULootObjectGUID`). Для процедурных объектов обязан выводиться из сида |
| **Персональный лут** | Вариант, когда каждый игрок видит свой набор в одном контейнере (`bIsUniqueLoot` + `UniqInventoryes`) |
| **Экипировка** | Слоты по `GameplayTag`, склейка мешей тела, FPS/TPS-виды (`EquipManager`) |
| **Комбо-граф** | Граф последовательностей атак (Input → Execution → Jump/Portal/Reset), редактируется своим редактором |

## Что изменилось относительно черновика `Prototype.md`

| В черновике | В проекте | Почему |
|---|---|---|
| «runtime-генерация», но шаги описаны как офлайн-пайплайн | Полностью рантайм: мир рождается из сида при подключении | Требование клиент-серверной архитектуры |
| Мир фиксированный 9 × 9 км, чанки 500 м | Размер мира — параметр генплана; участок 256 м | Мир переменного размера; бюджеты стриминга |
| Чанки как независимые файлы с дельтами | Единая формула участка от генплана, никаких файлов | Швы («эрозия краёв») исчезают по построению |
| Один линейный конвейер по всему миру | Два уровня: генплан (глобально) + участок (локально) | Иначе участок нельзя построить отдельно |
| Маски в одной RGBA8-текстуре | Отдельные слои на участок + правило, что является источником правды | Разная семантика и точность; RVT — не источник правды |
| «Перезапускается первый блок» | Фиксированные пассы генерации, каждый — чистая функция | Детерминизм и воспроизводимость |
| 16-битные высоты в RAW16 | Целые сантиметры (`uint16`), глобальная линейная карта | Недопустима нормализация по каждому участку отдельно |
| Стандартный ландшафт UE | Свой меш-террейн | Ландшафт нельзя создать в рантайме |
| ДТП и эвенты в генерации мира | Отдельная рантайм-подсистема, потребляет граф дорог | Это не генерация, это события |
