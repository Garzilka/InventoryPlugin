# 01. Правила одинакового мира

**Статус:** ✅ согласовано
**Выбранный уровень:** «Г» — гибрид. Критичное для игры считается целыми числами и обязано
совпадать всегда; внешний вид считается как удобно и не синхронизируется.

---

## 1. Что критично, а что косметика

| Критично (целые числа, совпадение обязательно) | Косметика (дробные числа допустимы, синхронизация не нужна) |
|---|---|
| Высоты рельефа | Цвет травы, оттенок земли |
| Маски (лес, грязь, камень, русло) | Плотность отдельных травинок |
| Где стоит дерево / камень / дом / контейнер | Мелкий декор: цветы, веточки, трещины |
| Дороги и реки (положение, ширина, профиль) | Следы на земле (визуальные) |
| Сетка проходимости | Покачивание растительности от ветра |
| Уклон, по которому нельзя ехать | Звуки, партиклы |
| Позиции и хеши структур | Внутренние детали зданий, которые нельзя потрогать |

Правило-проверка: **если расхождение может изменить геймплей — это критичное, значит целые числа.**

## 2. Случайность

### 2.1 Запрещено: генератор с состоянием

```
// ТАК НЕЛЬЗЯ
rand()           → 41
rand()           → 18467
rand()           → 6334
```

Причина: результат зависит от того, сколько раз генератор вызвали до этого. Добавили новый
куст — сдвинулись все деревья после него. Запустили в другом порядке или в другом потоке —
другой мир.

### 2.2 Требуется: счётная случайность (хеш от входов)

```
// ТАК НУЖНО
случайное = хеш(сид_мира, назначение, номер_участка_X, номер_участка_Y, ключ)
```

Одно и то же на входе — всегда одно и то же на выходе. Порядок вызовов, количество потоков
и повторные запуски не влияют.

Реализация (splitmix64 — только целочисленная арифметика, переносима между платформами):

```cpp
static inline uint64 Hash64(uint64 x)
{
    x += 0x9E3779B97F4A7C15ull;
    x  = (x ^ (x >> 30)) * 0xBF58476D1CE4E5B9ull;
    x  = (x ^ (x >> 27)) * 0x94D049BB133111EBull;
    return x ^ (x >> 31);
}

uint32 RandomU32(uint64 WorldSeed, uint32 Purpose, int32 CX, int32 CY, uint64 Key)
{
    uint64 H = WorldSeed;
    H = Hash64(H ^ Purpose);
    H = Hash64(H ^ (uint64)(uint32)CX);
    H = Hash64(H ^ (uint64)(uint32)CY);
    H = Hash64(H ^ Key);
    return (uint32)(H >> 32);
}
```

### 2.3 Как пользоваться: проверка плотности в целых числах

```
// Плохо: 0.6 — дробное, на границе может решиться по-разному
if (RandomFloat() < 0.6f) ...

// Хорошо: плотность — целое 0..10000
if (RandomU32(Seed, Purpose::Grass, CX, CY, CellKey) % 10000 < Density) ...
```

### 2.4 Реестр назначений (Purpose)

Каждый вид случайности получает свой постоянный номер. Добавление нового назначения не должно
сдвигать существующие.

| Диапазон | Назначение |
|---|---|
| 1–99 | Рельеф: шум, микрорельеф, штампы |
| 100–199 | Маски и поля |
| 200–299 | Вода: русла, озёра, берега |
| 300–399 | Дороги: развилки, обочины |
| 400–499 | Растительность (деревья, кусты, трава) |
| 500–599 | Камни и мелкий декор |
| 600–699 | Структуры: варианты зданий, окна, крыши |
| 700–799 | Промзоны, военные объекты |
| 800–899 | Внутренние детали, лут |
| 900–999 | Служебное и отладка |

Номера фиксируются в коде и **никогда не меняются** (менять — значит менять мир; это делается
только вместе с `GENERATOR_VERSION`).

## 3. Числа

| Что | Формат | Пример |
|---|---|---|
| Позиции, высоты, размеры | `int32` в сантиметрах | 123.45 м → `12345` |
| Углы (поворот) | `uint16`, где 65536 = 360° | 90° → `16384` |
| Плотности, вероятности | `uint16` 0…10000 (доли от 10000) | 60% → `6000` |
| Время | `int64`, миллисекунды | |
| Цвет, оттенок (косметика) | допустимы `float` | |

### 3.1 Тригонометрия и прочие функции

| Функция | Можно? | Как |
|---|---|---|
| `+`, `-`, `*` на целых | ✅ | |
| Деление на целые | ✅ | только с явным округлением (`/` усекает — всегда документируй) |
| `sqrt` | ✅ | округление по IEEE-754 одинаково везде |
| `sin`, `cos` | ❌ из стандартной библиотеки | своя таблица 4096 значений + линейная интерполяция на целых |
| `pow`, `exp`, `log` | ❌ | таблицы или полиномы на целых |
| `atan2`, `acos`, `asin` | ❌ | таблица или «поворот вектора» на целых |
| Шум (Perlin/Simplex) | ⚠️ | только целочисленная реализация с целочисленными градиентами |

Причина: реализации этих функций различаются между компиляторами и платформами на уровне
последнего бита. Миллионы проверок в секунду превращают «последний бит» в другое дерево
на другом конце карты.

### 3.2 Где дробные числа всё-таки живут

- рендер (матрицы, материалы, анимация);
- звук;
- косметика, которая не участвует в решениях.

Граница проходит по функции: **если значение уходит в решение — оно целое.**

## 4. Порядок и параллельность

| Правило | Почему |
|---|---|
| Никаких `TMap` / `TSet` / `std::unordered_map` в генерации | Порядок обхода зависит от аллокаций |
| Только массивы + сортировка по стабильному ключу | Порядок известен |
| `ParallelFor` — только по независимым участкам | Каждый участок считается сам по себе |
| Никаких глобальных свёрток («отсортируем все деревья мира») | Порядок и потоки начнут влиять на результат |
| Обход соседей — в явно заданном порядке (например, по часовой с севера) | Иначе мелкие различия в порядке меняют результат |

## 5. Версии

| Версия | Что покрывает | Меняется когда |
|---|---|---|
| `FORMAT_VERSION` | Раскладка байтов в данных участка | Меняем формат файла/блока |
| `GENERATOR_VERSION` | Формулы генерации (шум, маски, карвинг) | Любое изменение, меняющее мир |
| `GRAPH_VERSION` | Графы PCG | Изменили композицию структур или декора |
| `LOOT_VERSION` | Наборы лута: строки, пресеты, правила, назначения RNG (800–899) | Меняли что-либо в лут-таблицах или формулах выдачи |
| `ASSET_VERSION` | Ассеты, влияющие на раскладку (габариты зданий) | Поменяли размеры/набор ассетов |
| `WORLD_VERSION` | Хеш от (сид, коды выше, параметры генплана) | Автоматически |

**Проверка при подключении:** клиент присылает `WORLD_VERSION`. Не совпало — сервер отказывает
с понятным сообщением («версия мира не совпадает, обновите клиент»), а не пытается «как-нибудь».

## 6. Проверка в CI (обязательно с первого дня)

1. **Эталонные сиды:** `1`, `42`, `1337`, `0x9E3779B97F4A7C15`.
2. **Хеши сохраняются в репозиторий** (`Tests/Golden/*.hash`):
   - хеш генплана для каждого эталонного сида;
   - хеши участков (сетка 5 × 5 вокруг (0,0));
   - хеши выходных данных PCG для 2–3 участков.
3. **Расхождение = падение сборки.** Не «странный баг через месяц», а красный тест.
4. **Прогон на двух платформах** (Windows + Linux), если планируется Linux-сервер.
5. **Отдельный тест «PCG не читает физику и GPU»:** прогон графа до готовности коллизии и после
   должен давать одинаковый хеш (см. `03-pcg-contract.md`).

Обновление эталонных хешей — только вместе с повышением `GENERATOR_VERSION` и отдельным
коммитом «мир изменён осознанно».

## 7. Что делать при расхождении в бою

| Ситуация | Действие |
|---|---|
| Хеш участка у клиента не совпал с серверным | Сервер досылает раскладку структур и высоты участка (аварийный путь) |
| Клиент не может воспроизвести генплан | Сервер досылает генплан целиком (он маленький) |
| Массовые расхождения | Считается инцидентом: блокируем подключение, разбираемся |

Аварийный путь существует для того, чтобы игроки не страдали от багов, но **не заменяет**
детерминизм: если он включается часто — это ошибка, а не режим работы.
