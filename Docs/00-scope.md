# 00. Границы системы

**Статус:** ✅ согласовано
**Задача одним предложением:** мир (9 × 9 км или любого другого размера), который рождается
из сида при подключении игрока, выглядит как лесостепь с реками, дорогами, посёлками и
промзонами — и получается **одинаковым у клиента и сервера**.

---

## 1. Три участника системы

### 1.1 Сервер

Делает всё, что определяет **что мир из себя представляет**.

| Обязанность | Когда |
|---|---|
| Хранит сид мира и версию генератора | Постоянно |
| Строит **генплан** мира (горы, реки, дороги, города, промзоны, POI) | Один раз при старте мира |
| Строит **раскладку структур** по участкам (что где стоит) | Лениво, по запросу участков |
| Держит сущности (двери, контейнеры, предметы, техника) и их состояние | Постоянно |
| Авторитетно считает физику, движение, попадания | Постоянно |
| Принимает и хранит **правки игроков** (выкопал, сломал, построил, продавил колею) | Постоянно |
| Проверяет при подключении совпадение версии мира | При входе игрока |

**Чего сервер НЕ делает:** не строит меши, не красит землю, не ставит траву, не держит
готовую физику всего мира.

### 1.2 Клиент

Делает всё, что определяет **как мир выглядит**.

| Обязанность | Когда |
|---|---|
| Получает при входе сид, версию мира и генплан (или его хеш) | При подключении |
| Строит данные участков из генплана теми же формулами | По мере стриминга |
| Строит меши, юбки, коллизию, нормали | По мере стриминга |
| Рисует раскраску земли (RVT) | По мере стриминга |
| Расставляет растительность и мелкий декор (PCG + HISM) | По мере стриминга |
| Собирает внешний вид структур по раскладке от сервера | По мере стриминга |
| Предсказывает своё движение и получает поправки от сервера | Постоянно |

**Чего клиент НЕ делает:** не решает, что где стоит в мире; не хранит мир целиком;
не придумывает раскладку структур.

### 1.3 Человек (контент)

Делает то, что процедурно делать бессмысленно и дорого.

| Сфера | Что делает |
|---|---|
| Ассеты | Здания, деревья, камни, техника, материалы, звуки |
| Коллизия ассетов | Готовится один раз в редакторе вместе с ассетом |
| Графы PCG | «Как выглядит»: композиция внутри зданий, промзон, декор |
| Параметры генплана | Стиль мира, плотности, правила размещения |
| Ручной контент | Отдельные «красивые места», если понадобятся (как исключения из процедуры) |

## 2. Четыре слоя данных и как они передаются

Главная таблица проекта: она определяет, где может возникнуть расхождение клиента и сервера,
а где его не может быть по определению.

| Слой | Кто решает | Как передаётся | Пример |
|---|---|---|---|
| **Генплан** | Сервер, один раз | При подключении, ~10–500 КБ | «Промзона №3 здесь, примыкает к ж/д здесь» |
| **Раскладка структур** | Сервер | По участкам, килобайты | «Ангар в (12043, 8702), поворот 90°, вариант 7731» |
| **Внешний вид и декор** | Клиент сам, по сидам | Никак | «Из сида 7731 собрать крышу, ворота, трещины» |
| **Интерактив и правки** | Сервер | Репликация состояния | «Дверь ангара №87 открыта», «здесь выкопана яма 1.5 м» |

Правила:

1. **Если клиент нарисует стену, которой нет на сервере — игрок упрётся в невидимую стену
   или пройдёт сквозь видимую.** Поэтому «что где стоит» всегда приходит от сервера данными,
   а не считается независимо.
2. **Внешний вид не влияет на игру** — его можно считать локально и не синхронизировать.
3. **Правки игроков — единственное, что нельзя пересчитать из сида**, поэтому они хранятся
   отдельно от процедурных данных.

## 3. Чего мы не делаем (и почему)

| Не делаем | Почему |
|---|---|
| Стандартный ландшафт UE (`Landscape`) | Создаётся только в редакторе, есть жёсткий предел размера (≈ 8160 × 8160 квадов) |
| `World Partition` | Редакторная система, для рантайм-мира не работает |
| Плагин Water | Заточен под ландшафт |
| Запекание мира в ассеты | Мир переменного размера и рождается из сида |
| Предрасчёт коллизии и физики всего мира | 14–50 ГБ данных и невозможность загрузить готовую физику в рантайме; при этом выигрыш только в отсутствии фризов, который закрывается иначе |
| PCG как «спавнер объектов» | У клиента и сервера получились бы разные объекты без общих ID — синхронизировать нечего |
| Свой NavMesh (пока) | Отложено; интерфейс «найди путь» заводим сразу, чтобы замена была локальной |
| Рантайм-деформация рельефа (пока) | Отложено вместе с техникой; колеи проектируем как отдельный тонкий слой |

## 4. Этапы (MVP)

| Этап | Что получаем | Критерий готовности |
|---|---|---|
| **MVP-1** | Один участок 256 м из сида: высоты, меш, юбки, коллизия; персонаж ходит | Игрок стоит на земле, провалов нет; участок генерируется ≤ 20 мс |
| **MVP-2** | Генплан (реки/дороги) + копание русел/полотна + стриминг нескольких участков | Можно пробежать 1 км без провалов и фризов > 30 мс |
| **MVP-3** | Раскладка структур с сервера + PCG-декор (трава, листва, камни) | Деревня выглядит как деревня; хеши участков совпадают у клиента и сервера |
| **MVP-4** | Города/промзоны, интерактив (двери, контейнеры), репликация, правки игроков | Игрок ломает/открывает/строит, состояние переживает рестарт сервера |
| **MVP-5** | Техника + грунт (сопротивление, следы; колеи — по желанию) | Машина вязнет в грязи и едет по траве |

### 4.1 Смежная система: инвентарь и лут

Инвентарь — не часть генерации мира, но потребляет её результат: раскладка структур говорит
«здесь стоит ящик», а что внутри — решает инвентарь (сервер). Границы этой связки:

| Решает мир | Решает инвентарь |
|---|---|
| Где стоит контейнер, какой у него лут-профиль | Что конкретно внутри и в каком количестве |
| ID объекта в мире (`Hash64(seed, cx, cy, kind, index)`) | Состояние предметов, переносы, торговля, экипировка |

Контекст кода — [`06-inventory-ecosystem.md`](06-inventory-ecosystem.md), контракт стыка —
[`07-worldgen-inventory-bridge.md`](07-worldgen-inventory-bridge.md).

## 5. Открытые вопросы (решаются на следующих шагах)

1. **Маски и поля** (шаг 5): точный список слоёв, правила «наложения» макро/микро,
   производные поля (уклон, сток, расстояние до воды, проходимость).
2. **Реки** (шаг 6): модель стока, поиск русел, озёра, профиль русла в генплане.
3. **Дороги** (шаг 7): классы, ограничения уклона, джанкшены, мосты.
4. **Города** (шаги 8–9): правила размещения, площадки под здания, подпорные стенки.
5. **Свой просмотрщик мира** (шаг 13): без него отлаживать рантайм-мир почти невозможно.
