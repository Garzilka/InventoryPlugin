# ADR-0008: Детерминированный лут и ID процедурных сущностей

- **Дата:** 2026-10-29
- **Статус:** принято
- **Связано:** [01-determinism.md](../01-determinism.md), [02-data-contract.md](../02-data-contract.md),
  [07-worldgen-inventory-bridge.md](../07-worldgen-inventory-bridge.md), [ADR-0004](ADR-0004-pcg-outputs-data.md)

## Контекст

Плагин инвентаря (`06-inventory-ecosystem.md`) решает две задачи недетерминированно:

1. **Случайность.** `ULootWorldSubSystem` использует `FMath::RandRange` (шанс блока, выбор строки
   по весу, количество предметов), а `UInventoryLibrary` — `FMath::RandRange` для количества.
   Результат зависит от порядка вызовов и состояния глобального RNG.
2. **Идентификаторы.** `ULootObjectGUID::AddToLootSystem()` создаёт `FGuid::NewGuid()` — случайный
   GUID, который живёт в ассете. Для процедурных контейнеров это означает: после перезапуска
   сервера сохранение не найдёт свой контейнер.

Правила проекта требуют обратного: мир рождается из сида и должен совпадать у клиента и сервера
(`01`, ADR-0001), а раскладка структур приходит данными с сервера (ADR-0004).

## Варианты

1. **Оставить как есть**, считать лут только на сервере и передавать состоянием.
2. **Считать лут на обеих сторонах** независимо и сверять хеши.
3. **Сделать лут счётной функцией** от (сид, участок, ID контейнера) и **выводить ID из сида**;
   на клиент по-прежнему уходит готовое состояние.

## Решение

**Вариант 3.**

- Лут считается **только на сервере** и передаётся клиенту как состояние (совпадает с ADR-0004).
- Вся случайность лута — `Hash64`-функция из `01-determinism.md` §2.2 с назначениями в диапазоне
  **800–899** («внутренние детали, лут»): `BlockChance`, `RowPick`, `Amount`, `ItemVariant`,
  `RespawnDelay`.
- Шансы и веса — целые (`0…10000`), количества и деньги — целые, время — секунды/миллисекунды мира.
- ID контейнера = ID структуры из `02` (`Hash64(seed, cx, cy, kind, localIndex)`), а GUID плагина —
  его hex-представление: `FName(FString::Printf(TEXT("%016llX"), Id))`.
- `FGuid::NewGuid()` разрешён только для ручных объектов, созданных в редакторе.
- Вводится `LOOT_VERSION` (набор строк, пресетов, правил и назначений RNG) и включается в
  `WORLD_VERSION`.

## Следствия

- ✅ Один сид → один и тот же лут; сохранения находят свои контейнеры после рестарта.
- ✅ Лут можно проверять golden-хешами в CI, как требует `01` §6.
- ✅ Клиент не может «вычислить себе другой лут» — он вообще не считает.
- ⚠️ Придётся патчить `LootWorldSubSystem`, `LootSystemData`, `InventoryLibrary`,
  `ULootObjectGUID` (см. `07` §5.2).
- ⚠️ Любое изменение лут-таблиц/формул = повышение `LOOT_VERSION` и новый эталонный хеш.
- ⚠️ Косметика (отдача, гильзы, декали) остаётся на `FMath::Rand` — это разрешено.
