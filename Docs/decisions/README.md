# Журнал решений (ADR)

Architecture Decision Record — короткая записка: **контекст → варианты → решение → следствия**.
Нужна, чтобы через полгода не спорить заново о том, что уже решено, и чтобы новые участники
понимали причины.

## Шаблон нового ADR

```markdown
# ADR-000N: Краткое название

- **Дата:** ГГГГ-ММ-ДД
- **Статус:** предложено / принято / отклонено / заменено ADR-000M
- **Связано:** ссылки на документы

## Контекст
Что вынудило принимать решение. Ограничения, факты, цифры.

## Варианты
1. ...
2. ...

## Решение
Что выбрали и почему именно это.

## Следствия
- ✅ что выиграли
- ⚠️ чем заплатили / что теперь обязаны делать
```

## Правила ведения

1. Один ADR — одно решение. Не сваливать «и еще заодно переименовали модули».
2. Принятое решение не переписывается. Если оно устарело — новый ADR со статусом «заменяет
   ADR-000X», а старый помечается «заменено».
3. Если решение требует кода-заглушки или проверки — это пишется в «Следствиях».
