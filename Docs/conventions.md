# Соглашения проекта

**Статус:** ✅ действует с 2026-10-29
**Область:** весь код, конфиги и документация (`Source/`, `Plugins/`, `Config/`, `Docs/`).

Правила появились из практики: часть файлов плагина была сохранена в cp1251, из-за чего русские
комментарии превратились в «кракозябры» и потерялись безвозвратно. Чтобы это не повторилось —
соблюдаем всё, что ниже.

---

## 1. Язык

| Что | Язык | Пример |
|---|---|---|
| C++ идентификаторы, имена файлов и папок, имена модулей | **Латиница** (требование UHT/компилятора) | `UBaseItem`, `ItemSystem`, `BaseItem.h` |
| Комментарии в коде | **Русский** | `/** Размер клетки предмета в интерфейсе */` |
| `DisplayName`, `ToolTip`, `Category`, `meta`-подписи | **Русский** | `meta = (DisplayName = "Система предметов")` |
| Тексты интерфейса (`FText`) | **Русский** | `LOCTEXT("Ключ", "Открыть")` |
| Документация (`Docs/`) | **Русский** | — |
| Имена Blueprint-переменных | Латиница, подпись — русская | `ItemCellSize` + `DisplayName = "Размер клетки"` |

Кириллица **запрещена** в идентификаторах, именах файлов и путях — это ломает UHT, сборку и
переносимость.

---

## 2. Кодировка

| Тип файла | Кодировка |
|---|---|
| `.h`, `.cpp`, `.cs`, `.ini` | **UTF-8 с BOM** |
| `.ps1` (временные скрипты) | **UTF-8 с BOM** или чистый ASCII |
| `.md` | UTF-8 без BOM |
| `.uproject`, `.uplugin` (JSON) | UTF-8 без BOM |

Почему BOM:

- UnrealBuildTool и MSVC без BOM читают файл как ANSI → русский текст превращается в мусор;
- PowerShell 5.1 без BOM читает `.ps1` как ANSI → скрипт падает с ошибкой парсера;
- git может «нормализовать» переводы строк, но BOM сохраняет, если не использовать
  `working-tree-encoding`.

Проверка и починка (скрипт в репозитории): `_tools\ensure_utf8_bom.ps1` — добавляет BOM всем
исходникам, где есть не-ASCII.

> ⚠️ Если в файле уже есть символ `U+FFFD` («кракозябра»), конвертация не поможет: текст потерян.
> Такой комментарий надо переписать заново.

---

## 3. Имена и структура

1. Папка модуля = имя модуля (`ItemSystem`, `InventorySystem`). Числовых префиксов нет.
2. Файл `Build.cs` называется по имени модуля: `ItemSystem.Build.cs`.
3. Include-путь всегда от корня `Source`:
   `#include "InventoryEcosystem/ItemSystem/Objects/Item/BaseItem.h"`.
   Относительные include (`../../..`) запрещены.
4. Префиксы UE соблюдаются: `U` (UObject), `A` (Actor), `F` (struct), `E` (enum), `I` (interface).
5. Модуль экспортирует типы макросом `ИМЯМОДУЛЯ_API` (`ITEMSYSTEM_API`, `INVENTORYSYSTEM_API`).
   При переносе типа в другой модуль макрос меняется вместе с ним.
6. Классы не переименовываются «по ходу»: переименование = отдельная задача + `CoreRedirects`
   в `Config/DefaultInventoryEcosystem.ini` (иначе рвутся Blueprint-ассеты).

---

## 4. Правка существующего файла — чек-лист

1. Файл в UTF-8 **с BOM** (если есть не-ASCII).
2. Русский текст читается, «кракозябр» нет.
3. `UPROPERTY`/`UFUNCTION` подписи — на русском.
4. Мёртвый код удалён, а не закомментирован.
5. Include-пути соответствуют текущей структуре модулей.

---

## 5. Запреты

| Запрещено | Почему |
|---|---|
| Сохранять исходники в ANSI/cp1251 | Текст теряется безвозвратно |
| Кириллица в именах файлов, классов, переменных | UHT/сборка/переносимость |
| Оставлять закомментированные блоки «на память» | Мёртвый код: `LootWorldSubSystem.cpp` был на 42 % из комментариев |
| Менять имя класса/модуля без `CoreRedirects` | Ломаются Blueprint-ассеты и сохранения |
| Добавлять зависимость модуля «на всякий случай» | Лишние связи, долгая сборка |

## 6. Git

`.gitattributes` (рекомендуется добавить):

```
* text=auto
*.h    text eol=crlf
*.cpp  text eol=crlf
*.cs   text eol=crlf
*.ini  text eol=crlf
*.uasset binary
*.umap   binary
```

Не использовать `working-tree-encoding` для `.h/.cpp` — он может срезать BOM.

---

## 7. Временные инструменты

Скрипты миграций лежат в `_tools/` и пишутся **в ASCII** (или UTF-8 с BOM), чтобы не зависеть от
кодировки консоли. После завершения работ папку можно удалить — она не входит в сборку.
